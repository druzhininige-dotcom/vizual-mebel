Wildberries · ИП Дружинин · снимок 12.10.2026
READ-ONLY

Семь агентов читают кабинет Wildberries и складывают находки в базу. Ни один шаг не меняет магазин: ответы на отзывы готовятся как черновики, названия карточек — как предложения.

Что требует внимания

Приоритеты P1/P2/P3 собираются из базы находок, а не перезапросом API — поэтому сводка всегда совпадает с тем, что видели агенты.

Состояние агентов

Каждый агент — отдельный модуль с общим набором флагов: --once (один прогон), --dry-run (ничего не отправлять), --fixture (работать по сохранённому ответу API, без сети), --send (доставить в Telegram владельцу).

Агент №1 читает все карточки через content-api и считает балл здоровья: фото, длина описания, заполненность характеристик. Ниже — тот же расчёт в браузере, по сохранённой выгрузке.

Агент №4 читает отзывы и вопросы, определяет тональность по тексту (а не только по звёздам) и готовит черновик ответа. Отправка в магазин выключена флагом actions.reviews_reply.enabled: false — сначала утверждает человек.

Агент №6 берёт заказы, продажи и остатки из statistics-api. Лимит WB жёсткий (общий бакет с отзывами — иногда до 160 минут ожидания), поэтому агент ходит один раз в сутки и складывает результат в базу.

Три правила, на которых держится система

1. Только чтение. Любое изменение магазина — за флагом в конфиге, включается по одному и по прямой команде владельца.

2. Нет данных — так и пишем. Если поле не отдаётся API (например, видео в content-api), агент пишет «нет данных» и причину, а не ноль.

3. Сначала сохранённый ответ. Тесты и демо идут по фикстурам: живой магазин не трогается и не расходует лимит запросов.
